## Final local acceptance sequence

1. Freeze source and save revision or source digest. Build/package with project scripts and retain exit codes/logs. Re-run integrated tests; explicitly opt into owned native fixtures and unique owned-Keychain tests, preserving skips rather than treating them as success.
2. Verify the final bundle's executable/resources, app identifier/minimumOS, MIT/dependency notices and trusted fixture path/digest/running signature contract. Ad-hoc verify/open is local packaging evidence only.
3. After any optional tester-approved keyboard/VoiceOver/caption preference changes, restore original preferences. None has been changed or approved by this ledger. Use the disposable verification store to observe every destination, keyboard path, history controls, diagnostic preview/export and stale/denied/gone states. Run an explicitly confirmed owned fixture stop and inspect exact target/results. Do not clear the founder's real store for a test.
4. Capture actual offline/network behavior, measure correctly converted CPU/RSS and menu latency, and save raw sanitized results with workload/baseline limitations. The invalid benchmark remains retained for audit.
5. Complete [beta-plan](beta-plan.md), minimumOS/reference hardware/accessibility/usability gates and any unresolved defect fixes before a release decision.

## Developer ID and notarization preparation

This is a manual preparation checklist; no credential, Apple upload or publication action is authorized by merely reading it. An operator must separately authorize use of an existing approved signing identity/notarization profile. Never install/change certificates, expose secrets in logs or bypass authentication UI.

Freeze candidate bits. Review bundle identifier/version/minimumOS, hardened-runtime entitlements, nested executable code, resources/licenses and the packaged trusted fixture. Sign nested code first with the approved Developer ID Application identity, hardened runtime and timestamp, then sign the app. Signing changes the fixture's code identity: regenerate/verify its trusted enrollment metadata for the final signed fixture before outer signing; an ad-hoc fixture CDHash cannot be assumed valid after re-signing. Verify exact running-code ownership/identity against the signed final fixture and repeat target safety tests.

Use `codesign --verify --deep --strict --verbose=2 <app>` for verification, not `--deep` as a substitute for deliberate signing of nested code. After explicit upload authorization, create the distribution archive and use `xcrun notarytool` with an already approved Keychain profile. Save submissionID/status/accepted-or-rejected log without credentials; fix rejection causes before another authorized submission. Staple accepted tickets with `xcrun stapler`, validate them, and run `spctl --assess --type execute --verbose=2 <app>`. Test the downloaded/quarantined artifact on a clean supported Mac, including offline launch, collector/Keychain behavior and no unexpected consent.

Publication/push/distribution require separate authorization. Publish exact source/license/notices/build instructions, measured compatibility/metric/adapter boundaries and known unknowns alongside the approved artifact. Finish remaining naming checks without reopening the approved name or buying a domain automatically. A notarization acceptance does not certify UX, metric accuracy or safe target selection.

## Evidence rules

Save command, timestamp, source/revision, environment/workload, exit code, failures/skips and limitations under docs/evidence. Screenshots must show actual observed UI; no generated mock evidence. Do not retain prompts, arguments, usernames, credentials or payloads. Keep failed/invalid evidence labeled, and rerun only gates affected by later changes. A future plan, pending log or test definition never counts as a pass.
