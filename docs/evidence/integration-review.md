## Critical CPU units finding: corrected in source

**P1, resolved in collector source; full integrated verification and new benchmark required.** [C collector](../../Sources/CAmid/collectors.c) formerly passed `ri_user_time + ri_system_time` and `pti_total_user + pti_total_system` directly to [Sampler](../../Sources/AmidCore/Collection/Sampler.swift), which divided the delta by 1,000,000,000 as nanoseconds. On this Apple silicon host both API paths expose Mach absolute-time ticks. The host timebase was 125/3 nanoseconds per tick. CPU was therefore underreported by about 41.6667 times, affecting application/process displays, CPU alerts, low-activity suggestions and observer-overhead evidence.

An isolated C executable created for this run consumed about two seconds of its own CPU. Reference `getrusage(RUSAGE_SELF)` user+system timeval deltas are converted from seconds/microseconds; no arbitrary process metadata was needed for the workload.

| Observation | Measured result |
| --- | --- |
| Before correction: collector rusage CPU delta | 47,967,225 raw ticks versus 1,998,595,000 reference ns; ratio 0.024000 |
| Independent task-info fallback check | 47,954,136 raw ticks versus 1,998,072,000 reference ns; ratio 0.024000 |
| After correction: same collector C path | 1,998,642,083 ns versus 1,998,598,000 reference ns; ratio 1.000022 |
| Swift real CPU regression, outside tool sandbox | Reference CPU 1.126145 s; interval 1.141253948 s; expected 98.6761% of one core; sampler measured 98.9139% |

The correction caches only `mach_timebase_info` using `pthread_once`, computes the sum and multiplication with `__uint128_t`, divides by the denominator and returns unknown on failure/overflow. Both rusage and task-info fallback use the same conversion. Memory quantities are unchanged. No assumption of a 1:1 timebase remains.

[CollectionTests](../../Tests/AmidCoreTests/CollectionTests.swift) `testCPUUnitsMatchOwnProcessReferenceWorkload` consumes more than one second of the test process's own reference CPU and compares measured percent against actual CPU/elapsed time. Its 15% tolerance allows sampling-boundary noise; the previous 2.4%-of-reference result fails decisively. The exact final CPU/marker-cache source harness ran seven cases outside the tool sandbox at 07:43:41, exit 0, zero failures/skips, including the owned TCP listener. The lazy-initialization regression subsequently added an eighth case. At 07:49:02 the exact eight-case collector harness ran outside the tool sandbox, exit 0, zero failures/skips. Its CPU reference was 1.126548 s, expected 99.90546%, measured 99.88952%.

The original collector benchmark reported 1,800.429985 s, 351 samples, mean raw-units CPU 0.017208482974%, mean collection wall time 0.037361407498 s and max observed memory 7,275,144 bytes. **Its CPU value is invalid**. Applying the host timebase factor estimates about 0.717020124% of one core for that old run, which is plausible beside about 37 ms of work per five-second interval; this is an audit estimate, not a replacement measured benchmark. The memory value is physical footprint, not full-GUI RSS. Retain the original as invalid evidence and rerun corrected collector/full-GUI benchmarks. Neither the old run nor a short corrected run closes the M1 reference gate or matched-baseline/wakeup requirements.

Safe hotpath changes accompanying the fix cache directory-marker existence only within one sample, preserving the twelve-ancestor limit and nearest-marker/explicit-root semantics; reuse one endpoint buffer for the current enumeration; and decode CWD once. No executable, identity, permission, CWD or endpoint observation is cached across samples. `testSharedAncestorMarkerCacheKeepsTraversalBoundAndFreshPublicLookups` checks bounded ascent and a new lookup after marker removal. Performance improvement remains unverified until the corrected run finishes.

## Data-loss and unsafe-action review results

The previous orphan-bucket resurrection issue has a meaningful source correction: HistoryStore now encrypts a manifest listing exact immutable bucket generation filenames, loads only that membership and reapplies exclusions. Files not in the manifest are not imported. [HistoryTests](../../Tests/AmidCoreTests/HistoryTests.swift) `testUncommittedEncryptedBucketCannotResurrectExcludedHistory` defines a regression. This closes the identified resurrection mechanism at source level; it does not substitute for final stable test evidence or directory-durability verification.

Key retrieval separates existing-key reads from creation; a missing/wrong key does not silently replace the key for an existing ciphertext archive. AES-GCM authenticated envelopes and ciphertext-only restrictive staging avoid a plaintext journal/fallback. Clear preserves explicit preferences/aliases but removes active history segments, actions/alerts and RAM samples. Symlink directory rejection and fail-closed tests exist. Review found no new plaintext persistence path; live Keychain/crash/migration/clear/exclusion behavior still needs its final observed run.

Within the declared trusted-fixture scope, review found no numeric-PID/group kill or force-kill path. [ActionController](../../Sources/AmidCore/Actions/ActionController.swift) obtains a genuine audit token, checks current identity/project/CWD/endpoints/ownership, verifies a running Security-framework guest against trusted CodeDirectory hash and hashes only the explicitly trusted bundled executable. Single-use confirmation is consumed before awaits and dispatch uses token-bound SIGTERM exactly once. General Node/Python/Swift/model/database/container/terminal targets remain disabled. [ActionSafety](../../Sources/AmidCore/Actions/ActionSafety.swift) rejects shared port numbers, metadata changes and changed descendants; another owner of a reused port is reported rather than targeted.

Owned fixture evidence (local record: `action-fixtures.log`) records successful live trusted stop, already-exited zero-signal behavior, Node/Python natural exit, restart identity and running-image substitution refusal. These narrow facts do not prove arbitrary production-server safety or minimum macOS 15 behavior. Metadata changes remain separate from atomic token incarnation checks; the known no-fork/no-exec fixture bounds this scope. No safety claim extends to compromised same-user processes, injected code or untrusted adapters.
