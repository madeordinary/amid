# Navigation and history verification candidate

On 2026-10-03, `build/AmidReview.app` packaged and passed strict ad-hoc verification. The [source and executable manifest](review-candidate-source.json) covers all 83 source, test, resource and script files checked unchanged before and after the full release suite and package. This is a local development candidate; no native observation or public binary release is implied.

The full release suite passed **153 tests with nine explicit profiling skips and zero failures** in 138.006 seconds. Nine deterministic C reply cases also passed. Native Node/Python/Swift, the independently pinned owned server, unique owned Keychain namespace, IPv4/IPv6/wildcard endpoint, application/project attribution and storage failure cases ran without correctness skips. Local raw logs use the `final-review-20261003-160949` prefix. An earlier 140-test run passed but source changed during execution; it is not the final candidate evidence.

The UI now has application-detail buttons in the menu panel, observed TCP ports beside project names and a collapsed System details section beneath the main Overview. Explicit group navigation clears a previous search even when selecting the same group again. Model navigation is tested; actual menu dismissal, selection visibility, layout, focus and VoiceOver still require native observation on this bundle.

History loading fetches one existing encryption key for each synchronous load and reuses it through load-time persistence. Reopening fetches the key again. Tests cover missing/wrong keys, invalid envelopes and later-segment tampering without manifest replacement or key creation. The verification-only [retained fixture importer](../verification-history-fixture.md) rejects malformed requests, unexpected hashes and unsafe paths; it copies ciphertext into a fresh owned directory and stops on failed import/load without opening the normal store. An initial Foundation temporary-path normalization defect was caught by the real fixture test and corrected before the passing suite.

Growth was concentrated in enforcement and persistence grouping; this identifies the next measured optimization target, not a completed fix.

Whole-process differences between short live runs are not attributed to that change. Collector production source remains unchanged. These diagnostics do not replace the earlier failed full-GUI budgets or provide a sustained/reference-hardware pass.
