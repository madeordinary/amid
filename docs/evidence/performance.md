The successful optimized probe command was `.build/release/amid-probe --benchmark 1800`; exit0, report `collector-benchmark-optimized.json`. It measured the collector path optimizations. Later display-group caching, unsorted history/alert grouping, conditional retained-history UI copies and window-visibility cadence changes are not measured by that report. The CLI probe continues independently of GUI visibility; it does not exercise SwiftUI, encryption, notifications or native menu opening.

Full GUI measurement uses `--performance-verification --benchmark-retention week --benchmark-hidden --benchmark 1800 --benchmark-output <absolute-json-path>` on a separately copied bundle. Its intended protocol is30seconds warmup, all accessible metadata, temporary encrypted history, then hidden-window measurement. Verify that the app actually starts and the report is produced; process launch alone is insufficient. The old silent benchmark was quit through its own UI. The resumed com.madeordinary.amid.benchresumed instance was reidentified and quit at about 15:40; its finalized report hash was unchanged. The newer com.madeordinary.amid.benchacceptance instance invalidated on another screen lock, finalized its report, and was quit through its own UI at about 18:42. Its 0.333395% CPU included the suspended tail and cannot pass active monitoring; peak RSS was133,267,456 bytes. The [final invalid report](gui-benchmark-acceptance-invalid.json) is preserved. The fresh checkpoint-source run completed continuously and failed both budgets, as described in [evening evidence](evening-ui-observations.md). It was quit normally and its final report hash stayed unchanged. Profile and fix measured costs before repeating a fresh final-source copy. Host Mac17,9/24GiB/15logicalcores is not the reference hardware. No user workload should be terminated for cleanup.

The full-GUI report should include a continuous active-monitoring window; lock/sleep/suspended intervals invalidate an ordinary background-cost comparison unless separately accounted for. `getrusage` CPU timeval deltas avoid the libproc Mach-tick unit error. Darwin peakRSS is a process-lifetime byte maximum, including warmup. The current harness reports interval context-switch deltas, which are not wakeups. Separate public own-process libproc interrupt/package-idle deltas are optional; missing or regressed counters remain unknown. Older reports may contain lifetime context-switch counts and are not relabeled.

No stack sampling was performed. Measurements used numeric own-process counters and source review; no stack profile is claimed.
