# Real fourteen-day beta plan

Status: not started/observed in this project evidence. This protocol preserves the PRD's real elapsed beta requirement; synthetic tests and accelerated clocks do not close it. No users were contacted, enrolled or instrumented by this task. The founder may start voluntary dogfood after the stable local acceptance gates in [release-gates](release-gates.md) pass.

## Entry criteria and record

Use a frozen identified candidate with passing target-safety and encrypted-history tests, final bundle/open evidence and no known unintended-stop/data-loss defect. Record actual start/end dates, candidate revision/hash, OS/model/RAM, history choice, notification permission and declared supported adapters. Recommend seven-day retention but require explicit choice; launch/login/notifications start off, update requests absent. Explain permitted process/path metadata, exclusions, local encryption, exports outside deletion guarantees and generic servers remaining read-only.

Use normal builds/renders, browsers/Electron apps and native Node/Python/Swift projects. Never collect prompts, source contents, arguments, environments, credentials or network payloads in the diary. No analytics, automatic crash upload, user contact or feedback upload is installed. Participants explicitly choose what sanitized feedback to share.

## Daily observations

| Exercise | Local diary fields |
| --- | --- |
| Ordinary work and alerts | Expected build/render, rule/entity alias, start/update/recovery, missing coverage, notification eligibility versus actual OS delivery, unwanted repeat and exclusion effect. |
| Projects/ports | Known test project/port, observed root/owner/family/scope, unknown owner/denied state, incorrect merge and reproduction using disposable fixture. |
| History/controls | Chosen retention, visible minute/hour spike/extrema/gaps/method labels, pause/resume, lower retention, cap notice, clear of disposable store and restart behavior. |
| Lifecycle/power | Sleep/wake/lock/quit/relaunch, actual observation gap/fresh CPU baseline; battery/AC and naturally observed thermal changes; no forced heat or user-process termination. |
| Supported stop | Only an explicitly confirmed disposable enrolled fixture; preview identities/endpoints, cancel/expiry/change cases, result/remaining listener, no retry/force kill. |
| Native UX | Keyboard paths/focus, VoiceOver labels/units/grouping/exact target, contrast/motion/light/dark/scaling and menu response. |

Review the diary periodically for correctness and repeated unwanted alerts after expected workloads are excluded. Compare notification episodes per category/entity with the one-hour cooldown; do not infer delivery from an eligibility flag. Record failures/missed events and denied coverage alongside successes. Investigate using an owned fixture; never stop the participant's existing server, editor, terminal, database or model runtime for a test.

## Usability and performance

With voluntary new users, time identification of the largest observed app memory consumer (target≤2min) and mapping of a known disposable port to the correct project. Record completion time, confusion and error, not a fabricated satisfaction score. Complete the separate reference-M1/newer-Mac baseline/30min correctly converted CPU/RSS/wakeup and menu-p95 protocol; a diary does not replace measurements.

## Exit review

At fourteen real days, save a dated report with actual participant count/exposure, revisions, observed workflows, expected-work exclusions, repeat alerts, correctness/action/data-loss defects and all hardware/accessibility/usability limitations. Substantial collector/action/storage/alert changes restart the affected validation exposure or explicitly bound which results still apply; do not silently credit changed behavior with old exposure. Resolve unintended-stop or data-loss defects before release. Remaining minimumOS/hardware/credentials/publication gates stay open even when dogfood finishes. Distribution remains a separately authorized human decision.
